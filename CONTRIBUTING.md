# Участие в проекте

Спасибо за интерес к ArcTune! Этот документ описывает правила, стиль кода и процесс
внесения изменений.

---

## С чего начать

1. Прочитайте [README.md](README.md) и [docs/safety.md](docs/safety.md).
2. Настройте окружение по [docs/development.md](docs/development.md).
3. Посмотрите [docs/roadmap.md](docs/roadmap.md) — там задачи с меткой.
4. Для больших изменений сначала обсудите идею (issue), чтобы не потрудиться зря.

---

## Правила проекта (инварианты)

Эти правила **не** обсуждаются — они защищают пользователей:

1. **Никогда не реализовывать** обход лимита питания выше аппаратного, запись/мод
   vBIOS и доступ к таймингам памяти (страпам). Это вне scope по определению.
2. **Read-only по умолчанию.** Любая операция, меняющая состояние карты, должна быть
   явной, оповещать пользователя и проходить проверки диапазонов.
3. **Безопасность важнее удобства.** Если компромисс между «просто» и «безопасно» —
   выбираем безопасно, даже если это больше кода.
4. **Честность о границах.** Если что-то не работает/не поддерживается на B580 —
   пишем об этом прямо в документации, не притворяемся что умеем.

Нарушение этих правил = отказ в слиянии, даже если код красивый.

## Процесс

1. Fork / ветка: `feat/краткое-описание`, `fix/описание`, `docs/описание`.
2. Коммиты по conventional commits (см. ниже).
3. Все тесты и линт должны проходить перед merge.
4. Изменения, затрагивающие запись настроек (`tuner.py`), требуют:
   - обновления [docs/safety.md](docs/safety.md) при появлении нового риска
   - теста на проверку диапазонов
5. PR с описанием: что меняется, почему, как проверено на железе.

## Коммиты (Conventional Commits)

```
feat: добавлено чтение телеметрии питания
fix: исправлен резолв ctlOverclockPowerLimitGetV2
docs: уточнены ограничения B580 в overclocking.md
test: тест layout структуры _ctl_power_telemetry_t
refactor: разделён loader и api
chore: настройка pyproject
perf: кэширование handle устройства
```

Первое слово — тип, далее — по-русски суть изменения. Тонна тела коммита приветствуется
для сложных решений.

## Стиль кода

- **Форматирование и линт:** `ruff` (конфиг в `pyproject.toml`). Перед коммитом:
  ```powershell
  ruff format .
  ruff check --fix .
  ```
- **Типы:** type hints **обязательны** для всех публичных функций и полей dataclass.
- **Docstrings:** Google style на всех публичных функциях/модулях.
- **Именование:**
  - низкоуровневый слой `igcl/` — повторяет C-имена IGCL без изменений
    (`ctlOverclockPowerLimitSetV2`, поля `_ctl_power_telemetry_t`)
  - высокоуровневые модули — snake_case, понятные Python-имена
- **Ошибки:** не «глотать». Код ошибки IGCL → исключение `IgclError`, а не тихий дефолт.
- **Комментарии:** объясняют *почему*, а не *что*. «что» должно читаться из кода.

### Пример сигнатуры

```python
def read_power_telemetry(adapter: AdapterHandle) -> PowerTelemetry:
    """Снимает телеметрию питания и причин ограничения карты.

    Read-only операция, безопасна.

    Args:
        adapter: handle устройства Arc.

    Returns:
        Снимок датчиков и флагов ограничения.

    Raises:
        IgclError: если IGCL вернул не-успешный код.
    """
```

## Тесты

- Новый код должен иметь тесты.
- Тесты на **layout структур** обязательны при изменении `types.py` — ловят рассинхрон
  с C.
- Тесты, требующие реального Arc, помечайте маркером `hardware` — они пропускаются без
  железа:
  ```python
  @pytest.mark.hardware
  def test_enumerate_b580():
      ...
  ```
