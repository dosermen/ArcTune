# ADR-0003: Инлайновая локализация tr(ru, en) вместо Qt .ts

## Статус

Принято

## Дата

2026

## Контекст

Проект двуязычный (русский — основной, English — полная версия). Нужен механизм
локализации для GUI (PySide6) и CLI. Стандартный Qt-путь — `.ts`/`.qm`-файлы
и `QTranslator`, но он тянет за собой инструменты lupdate/lrelease, отдельный
цикл сборки и не покрывает CLI.

## Решение

Инлайновая локализация: функция `tr(ru: str, en: str | None)` в `arctuner/i18n.py`,
строки пишутся прямо в коде. Выбор языка хранится в `~/.arctune/language`
(`"ru"`/`"en"`); приоритет у переменной окружения `ARCTUNE_LANG` (удобна для
тестов и CLI-сессий). Один и тот же файл читают GUI и CLI, поэтому переключатель
в меню «Вид» действует и на командную строку.

Правила честности перевода:

- термины IGCL (min/max/step, waiver и т.п.) не искажать — пишутся как в API Intel;
- машинные поля журнала (logbook JSONL, CSV-заголовки) всегда английские — это
  данные для парсеров, а не интерфейс.

## Плюсы

- Ноль инфраструктуры сборки: нет `.ts`/`.qm`, нет компиляции переводов.
- Перевод виден при ревью кода рядом со строкой; риск «мёртвого» ключа исключён.
- Покрывает и GUI, и CLI одним механизмом; тесты задают язык через env.

## Минусы

- Строки дублируются в коде (ru + en в одном вызове) — длинные строки GUI
  немного громоздки.
- Нет форматирования множественного числа и плюральных форм, как в gettext;
  для текущего объёма UI это приемлемо.
- Qt-инструменты (Qt Linguist) не используются — привычный пайплайн недоступен.
