# ADR-0005: V2 Get-функции — динамический вызов через loader

## Статус

Принято

## Дата

2026

## Контекст

Для честного «было → стало» в журнале перед записью tuner.py читает фактические
текущие значения OC-пунктов (их могло выставить другое ПО, а `info.default` —
это заводское значение). В IGCL для этого есть пять V2 Get-функций
(`ctlOverclockGpuFrequencyOffsetGetV2`, `ctlOverclockPowerLimitGetV2`,
`ctlOverclockTemperatureLimitGetV2`, `ctlOverclockVramMemSpeedLimitGetV2`,
`ctlOverclockGpuMaxVoltageOffsetGetV2`). Каждая из них доступна не во всех
версиях драйвера.

## Решение

Пять функций `...GetV2` вызываются из `tuner.py` динамически через loader —
без статических обёрток в `api.py`:

- маппинг «OC-поле → имя функции» — словарь `_CURRENT_GETTERS` в `tuner.py`;
- перед вызовом проверяется `api.loader.has(func)`; отсутствующая функция →
  значение `None`, а не ошибка;
- `ctlOverclockWriteCustomVFCurve` — случай особый: в `api.py` она
  *настраивается* (argtypes/restype при наличии в DLL), а вызывается из
  `tuner.py` через `api.loader.dll` с преобразованием кода ошибки в `IgclError`.

Отсутствие функции или ошибка чтения трактуются как «значение неизвестно»
(`None`) — запись при этом не блокируется.

## Плюсы

- `api.py` не разрастается обёртками, которые нужны только одному потребителю;
- наличие функции проверяется по факту на конкретной DLL (поддержка старых
  драйверов без V2);
- маппинг полей виден в одном месте рядом с кодом, который его использует.

## Минусы

- Имена функций заданы строками — опечатка обнаружится только в рантайме
  (частично закрывается тестами);
- нет единого Python-типа для V2-вызова, аргументы оформляются вручную
  (`ctypes.c_double`, `byref`);
- поведение «ошибка чтения → None» может замаскировать реальную проблему драйвера
  в журнале (принятый риск: честность «было → стало» важнее).
