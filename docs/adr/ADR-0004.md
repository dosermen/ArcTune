# ADR-0004: Рестарт onefile-exe через QProcess с чистым окружением

## Статус

Принято

## Дата

2026

## Контекст

GUI (PySide6) собирается PyInstaller в onefile (`arctune-gui.exe`). Переключение
языка или масштаба требует перезапуска приложения, и GUI умеет перезапускать себя
сам. Но onefile-сборка ломает наивный «запусти себя же»:

- сам процесс несёт `_PYI_ARCHIVE_FILE` / `_PYI_APPLICATION_HOME_DIR` (и легаси
  `_MEIPASS2`), указывающие на его `_MEIxxxx`;
- дочерний процесс унаследует их — его bootloader считает, что распаковка уже
  сделана, и стартует из ЧУЖОГО `_MEIxxxx`;
- первый инстанс при выходе удаляет свой `_MEIxxxx` → дочерний падает
  с «Failed to import encodings module» / «No such file or directory: encodings».

## Решение

`restart_env()` в `gui/scale.py` строит `QProcessEnvironment.systemEnvironment()`,
удаляет из него все переменные `_PYI*` и легаси `_MEIPASS2`; остальное окружение,
включая `QT_SCALE_FACTOR`, сохраняется. Тогда дочерний bootloader распакуется в
свой собственный свежий `_MEIxxxx`.

Перезапуск — через экземпляр `QProcess` (`window.py: _on_restart`): `setProgram`,
`setArguments` (`restart_argv()`: `[]` для frozen exe, `-m arctuner.gui.main`
для исходников), `setProcessEnvironment(restart_env())`, `startDetached()`; при
успехе родитель закрывается через `close()` (корректное закрытие сессии IGCL в
потоке воркера), при неудаче — диалог «запустите вручную». Статический
`QProcess.startDetached(..., env)` в PySide6 6.12 недоступен, поэтому используется
инстансный путь.

## Плюсы

- Перезапуск в onefile-сборке надёжен: дочерний процесс всегда стартует «с нуля».
- Диагностика проста: причина (наследование `_PYI*`) локализована в одном файле.
- Чистый fallback: если авто-старт не удался, пользователь видит понятную подсказку.

## Минусы

- Сборка процесса через экземпляр QProcess многословнее статического метода.
- Зависимость от деталей PyInstaller/PySide6: при обновлении PySide6 (появление
  статического `startDetached` с env) код стоит упростить.
