# ADR-0001: Read-only по умолчанию

## Статус

Принято

## Дата

2026

## Контекст

ArcTune работает с дискретными Intel Arc (проверено на B580) через IGCL: может
читать телеметрию и менять настройки разгона. Любая ошибка записи или неверное
значение — реальный риск нестабильности и, в худшем случае, повреждения железа.
Пользователь должен понимать, что именно меняется на его карте.

## Решение

Read-only — режим по умолчанию во всём проекте: CLI, GUI, autotune.

- Любая запись — явная операция: отдельная команда `set`/`vf --apply`/`fans --set`
  в CLI и диалог подтверждения в GUI. Молчаливой записи не бывает нигде.
- Перед записью значения проверяются min/max/step/IsSupported из
  `ctlOverclockGetProperties`; записи вне диапазона драйвера не происходит.
- GUI проверяется тем же кодом `tuner.py`, что и CLI, — две реализации проверок
  не разъезжаются.

Инварианты, которые не пересматриваются никогда:

- никаких обходов аппаратного лимита питания (~226 Вт / 120% от 190 Вт по шунту);
- никакой записи или модификации vBIOS;
- никакого доступа к таймингам памяти (страпам) — IGCL их не экспонирует.

Безопасность важнее удобства: если честная проверка из драйвера конфликтует с
удобством пользователя, побеждает проверка.

## Плюсы

- Пользователь всегда контролирует, когда карта меняется; ничего «случайного».
- Драйвер остаётся последним рубежом: проект не даёт выйти за аппаратный предел.
- Прозрачная граница scope: страпы/vBIOS/обход лимита — вне проекта навсегда.

## Минусы

- Больше кликов для записи (подтверждения, `--force` для 21–22 Гбит/с памяти).
- Часть «интересных» возможностей разгона принципиально недоступна — это осознанный
  отказ, а не пробел.
