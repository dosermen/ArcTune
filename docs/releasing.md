# Подготовка GitHub Release

Релиз собирается GitHub Actions workflow `Release` при отправке тега `vX.Y.Z`.
Workflow проверяет формат и соответствие тега версии в `src/arctuner/__init__.py`,
наличие датированной секции в `CHANGELOG.md`, затем запускает тесты и собирает
Windows x64 CLI/GUI архивы с SHA-256 контрольными суммами.

Проект пока имеет статус Alpha, поэтому автоматически созданный GitHub Release
помечается как предварительный (pre-release). Workflow не публикует пакет в PyPI.

## Выпуск новой версии

1. Убедитесь, что все нужные изменения находятся в `main`, нет незакоммиченных
   релизных правок и рабочее дерево не содержит пользовательских файлов.
2. Установите новую версию в `src/arctuner/__init__.py` по SemVer:
   - PATCH — исправления без новых возможностей;
   - MINOR — новые возможности с обратной совместимостью;
   - MAJOR — несовместимые изменения.
3. Перенесите готовые пункты из `[Unreleased]` в новую датированную секцию
   `CHANGELOG.md`, например `## [0.3.0] — 2026-11-27`, и оставьте пустую секцию
   `[Unreleased]` выше неё.
4. Обновите номер примера тега в `.github/workflows/release.yml`, если это
   требуется для сопровождаемости.
5. Локально выполните проверки, заданные в workflow:

   ```powershell
   ruff format --check .
   ruff check .
   python -m mypy src/arctuner
   python -m pytest -m "not hardware" -q
   ```

6. Проверьте релизные артефакты на чистом Windows x64 окружении. В GitHub Actions
   сборка выполняется отдельно; GUI проверяется на наличие файла, CLI запускается
   с `--version` без обращения к карте.
7. Зафиксируйте релизные изменения conventional commit-коммитом и отправьте `main`.
8. Создайте и отправьте аннотированный тег, совпадающий с версией:

   ```powershell
   git tag -a v0.3.0 -m "release: 0.3.0"
   git push origin main
   git push origin v0.3.0
   ```

9. Дождитесь зелёного workflow `Release` в GitHub Actions. Проверьте состав
   опубликованного релиза и SHA-256 суммы архивов перед распространением.

Если проверки или сборка не прошли, не создавайте новый тег для той же версии:
исправьте проблему, обновите релизный коммит и используйте новый patch-номер.
