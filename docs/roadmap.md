### Подтверждено живым API (Intel-данные с B580)

- `powerLimit`: **50...120 %** (потолок 120 % ~= 226 Вт — шунт, аппаратно)
- `vramMemSpeedLimit`: **19...22 Гбит/с** (сток 19, номинал чипа 20, драйвер до 22)
- `gpuFrequencyOffset`: **-300...+1000 МГц**, `temperatureLimit`: **60...100 °C**
- Датчики читаются: ядро ~1.0 В, память 1.35 В / ~19.75 ГТ/с (Samsung)
- **Ватты из счётчиков энергии**: `gpuEnergyCounter`/`totalCardEnergyCounter`
  supported (единицы = Дж); средняя мощность = ΔE/Δt. На живой карте:
  GPU ~68 Вт, вся карта ~120 Вт при 65 % от лимита питания
- **Ватты памяти** (`vramEnergyCounter`, Дж) — тем же PowerMeter: на живой
  карте idle ~7 Вт; **VR-фазы** (ядро/память/SA) ≈ 52/64/55 °C idle;
  **фактическая пропускная способность памяти** (vramRead/WriteBandwidth,
  units BANDWIDTH_MBPS): 1703/252 МБ/с в покое; надбавка напряжения 0 %
  (`gpuOverVoltagePercent`). Поля с суффиксом `Counter`
  (`vramReadBandwidthCounter`/`vramWriteBandwidthCounter`) — unsupported,
  работающие поля без суффикса: `vramReadBandwidth`/`vramWriteBandwidth`
  (живой прогон 2026-10-19)

### Обёрнуто IGCL API (27 функций)

- **Инициализация и устройство** (4): `ctlInit`, `ctlClose`,
  `ctlEnumerateDevices`, `ctlGetDeviceProperties`
- **Разгон V2** (10): `ctlOverclockGetProperties`,
  `ctlOverclockWaiverSet`, `ctlOverclockResetToDefault`,
  `ctlOverclockReadVFCurve`, `ctlOverclockWriteCustomVFCurve`,
  `ctlOverclockGpuFrequencyOffsetSetV2`, `ctlOverclockGpuMaxVoltageOffsetSetV2`,
  `ctlOverclockPowerLimitSetV2`, `ctlOverclockTemperatureLimitSetV2`,
  `ctlOverclockVramMemSpeedLimitSetV2`
- **Телеметрия** (1): `ctlPowerTelemetryGet`
- **Вентиляторы** (7): `ctlEnumFans`, `ctlFanGetProperties`, `ctlFanGetState`,
  `ctlFanSetFixedSpeedMode`, `ctlFanSetSpeedTableMode`, `ctlFanSetDefaultMode`,
  `ctlFanGetConfig`
- **PCIe / прошивка / ECC** (5): `ctlPciGetProperties`, `ctlPciGetState`,
  `ctlGetFirmwareProperties`, `ctlEccGetProperties`, `ctlEccGetState`

Пять V2 Get-функций (`...GetV2`) `tuner.py` вызывает динамически через `loader`
для чтения фактических значений; отдельных обёрток в `api.py` у них нет.
`ctlOverclockWriteCustomVFCurve` настраивается в `api.py`, но вызывается из
`tuner.py` напрямую. Подробнее — [docs/igcl-api.md](igcl-api.md).

### Жёстко отказано драйвером (проверено записью, п. «Эксперименты»)

- **Память выше 21 Гбит/с на тестовой карте не подтверждена**: 21 — работает
  и откатывается; 22 (заявленный драйвером предел) может быть отклонён
  (`DATA_WRITE`, 0x40000013); 24 — отказ (вне диапазона). Выше — только vBIOS
  (вне scope).
- **Лимит температуры вне 60...100 °C невозможен**: 50/55/105/110 —
  `TEMPERATURE_OUTSIDE_RANGE` (0x44000005) от самого драйвера, не наша проверка.
- **Отрицательное смещение напряжения невозможно**: V2-функция декларирует
  только 0...100 % (min=0), легаси-функция в ±мВ отвечает `DEPRECATED_API`
  (0x44000009). Undervolt на B580 — только кривая V/F.
- **Waiver обязателен**: `ctlOverclockWaiverSet` перед записью напряжения,
  отрицательного смещения частоты и кривой V/F — иначе
  `WAIVER_NOT_SET` (0x44000008). Это была причина «ошибки при изменении» в GUI.
  Согласие пользователя — диалог подтверждения записи (текст честно упоминает waiver).

## Перспективное

Приоритеты: 1 — автоматизация разгона, 2 — наблюдаемость, 3 — новые данные IGCL,
4 — удобство CLI/GUI.

**Аудит IGCL API (128 функций): 27 используется через `igcl/api.py` и `tuner.py`.**
Обёрнуты: инициализация (4), разгон V2 (10), телеметрия (1), вентиляторы (7),
PCIe/firmware/ECC (5). Пять V2 Get-функций вызываются из `tuner.py` динамически,
без отдельных обёрток.
Не обёрнуты, в частности: память (4), ECC set (1), домены частот (3), GpuLock (2),
`ctlAllowPCIeLinkSpeedUpdate`, дисплейная подсистема (~80, вне scope).
Список разобран по сложности в разделе ниже.

### 1. Автоматизация разгона

- [ ] **Стресс-нагрузчик внутри проекта** — чтобы авторазгон не требовал внешний
      бенчмарк (сейчас `external_cmd` умеет запустить заданный процесс, но своего
      нагрузчика нет; без нагрузки поиск честно останавливается «нет нагрузки»)
- [ ] **Температурные алерты в GUI** — safety.md требует держать <80 °C, а GUI
      молчит о троттлинге; пороги: ядро/память, уведомление о Power/Voltage Limited
- [ ] **Постоянный watchdog вне авторазгона** — сейчас TDR (Event ID 4101),
      заморозка телеметрии и аварийная 85 °C проверяются только на время поиска.
      Нужен фоновый мониторинг в poll-цикле и, опционально, авто-откат OC через
      `tuner.reset_to_default`/rollback. ► Авто-запись без подтверждения — только
      явная опция при включении, каждое действие в logbook; TDR фиксируется как
      факт, а не «пруф вины разгона»
- [ ] **Софт-кривая вентилятора для B580** — драйвер даёт только FIXED
      (проверено: `supportedModes=0x2`); поверх него — машина состояний в
      worker: целевая температура → шаги RPM с гистерезисом ±3 °C, аварийное
      правило >85 °C → 100 %, при выходе — `ctlFanSetDefaultMode`. Единственный
      способ получить «тихо в покое, громко под нагрузкой». ► Периодическая
      запись: одноактное согласие (диалог с предпросмотром); домен вентиляторов
      — самый безопасный из записевых
- [ ] **Бенч-интеграция** (`arctune bench run`) — subprocess 3DMark/Unigine/OCCT
      → парс результата → `benchbook.jsonl`; хук в `autotune/engine.py`
      (внешний процесс уже запускается через `external_cmd`).
      Хрупкий парсинг: по одному бенчу за итерацию, честно маркировать версию
      бенча и сцену; не обещать поддержку до распарсивания на реальной машине
- [ ] **Планировщик правил** — «при запуске игры → игровой профиль, после
      выхода → тихий»; psutil-поллер поверх профилей, гарантированный откат в
      try/finally. ► Одноактное согласие на правило с полным предпросмотром,
      только безопасные домены (частота/питание/вентиляторы, не V/F)

## Намеренно вне scope

Эти вещи проект **не** будет реализовывать — чтобы не создавать ложных ожиданий:

- [ ] **Страпы / тайминги памяти** — firmware применяет их при memory training,
      IGCL не даёт доступа
- [ ] **Прошивка / мод vBIOS** — для B580 нет модов с повышенным лимитом, риск кирпича
- [ ] **Обход лимита питания выше 120%** — аппаратный потолок (шунт на плате),
      требует пайки, вне программной области
- [ ] **Регулировка напряжения памяти (VRAM voltage)** — на B580 не поддерживается:
      `vramVoltageOffset`/`vramFrequencyOffset` возвращают `supported=false`
      (min=max=0), Intel пометил их «Deprecated / No Longer Supported» в
      `igcl_api.h`, а legacy-функция `ctlOverclockVramVoltageOffsetGet` отвечает
      `CTL_RESULT_ERROR_UNSUPPORTED_FEATURE`. В телеметрии `vram_voltage_v = 1.35 В`
      — это факт, а не настройка: у 6× Samsung K4ZAF325BC-SC20 напряжение фиксировано.
      Соответствующих элементов нет ни в CLI, ни в GUI.
- [ ] **Дисплейная подсистема / LED / I2C-AUX** (~80 функций IGCL: sharpness, EDID,
      genlock, ArcSync, RGB и т.п.) — вне профиля «мониторинг + разгон»;
      в `igcl_api.h` они разобраны, но не обёрнуты намеренно
