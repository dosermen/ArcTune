# Методика разгона Intel Arc B580

Практические выводы из анализа железа (Samsung GDDR6 K4ZAF325BC-SC20, VRM на
Alpha & Omega, аппаратный лимит питания по шунту) и поведения Intel Graphics Software.
Читайте [safety.md](safety.md) перед применением.

---

## Ключевые факты о железе B580

| Параметр | Значение |
|---|---|
| TDP (номинал) | 190 Вт |
| Аппаратный лимит софта | 120% ≈ **226 Вт** |
| Память | 6× Samsung **K4ZAF325BC-SC20**, 16 Гбит (2 ГБ) ×32 = 12 ГБ, 192-бит |
| Номинал памяти чипа | **20 Гбит/с** (заводская карта ставит 19) |
| Напряжение памяти | 1.35 В (фикс. рельс) |
| VRM ядра | 6 фаз, AOZ5517QI (60A) |
| Контроль питания | NCP45496 + шунт 2 мОм на входе 12V |

---

## Важные ограничения (почему софтом дальше не уйти)

**Лимит питания 226 Вт — аппаратный.** Карта считает потребление по падению
напряжения на шунте 2 мОм. Драйвер не даёт превысить 120%. Обойти можно только
физически (shunt-mod), что вне области софта и вне области проекта.

**Страпы (тайминги памяти) недоступны.** Firmware применяет их при memory training.
IGCL не экспонирует тайминги. Разгон памяти = только частота.

**Напряжение памяти.** API `ctlOverclockVramVoltageOffset*` есть, но на B580 может
быть заблокирован драйвером (проверять через `IsSupported`/`IsReadOnly`). В UI поля нет.

## Порядок настройки (правильная последовательность)

> Главное правило: **одно изменение за раз.** Intel Graphics Software может крашнуться,
> если менять несколько параметров при уже разогнанной памяти. Поэтому порядок:

### Шаг 1. Память → 20 Гбит/с
Номинал чипа SC20, безопасно.
- `ctlOverclockVramMemSpeedLimitSetV2(20)`
- **Перезагрузка**
- Проверка: `ctlMemoryGetState` → 2500 МГц (2500×8 = 20000)
- Тест стабильности 10–15 мин

### Шаг 2. Лимит питания → 120%
Максимум, что даёт софт. Обычно стоит из коробки.
- `ctlOverclockPowerLimitSetV2(120)`

### Шаг 3. Напряжение ядра (offset), 30% → 40%
Есть запас по ваттам и прохладно — инвестируем в напряжение, чтобы частота держалась.
- Шаг +5–10%, после каждого — стресс-тест
- Следить: температура < 80 °C, карта не «упёрлась» в Power/Voltage Limited

### Шаг 4. Частота ядра (offset), +300 → выше (осторожно)
- Только после стабильного напряжения
- Шаг +25–50 МГц, стресс после каждого
- Если перестало расти FPS/скорость — откатить на шаг назад

### Шаг 5 (альтернатива). Кастомная кривая V/F
Более тонко: `ctlOverclockWriteCustomVFCurve`. Позволяет «прижать» низкие частоты к
меньшему напряжению (undervolt) — экономия ватт при той же частоте. Продвинутый уровень.

## Как понять, в чём карта упёрлась

Читайте телеметрию (`ctlPowerTelemetryGet`), поля-флаги:

| Флаг | Значение | Что делать |
|---|---|---|
| `GpuPowerLimited` | упёрлась в лимит питания (226 Вт) | софтом дальше не растёт, нужен shunt-mod |
| `GpuVoltageLimited` | упёрлась в напряжение | поднимать voltage offset |
| `GpuTemperatureLimited` | перегрев | улучшить охлаждение / снизить частоту |
| `GpuUtilizationLimited` | ждёт CPU (bottleneck на процессоре) | разгон GPU не поможет |
| `Vram*Limited` | ограничение по памяти | см. память |

**Пример из практики (B580):** при 3300 МГц / 1.055 В карта потребляла лишь ~153 Вт
при 64 °C — то есть **огромный запас** (~73 Вт) и лимит питания вообще не был
узким местом. Это типично для B580 при умеренном напряжении: карта скорее
ограничена напряжением/температурой, чем ваттами.

## Частые ошибки

1. **Сразу крутить частоту.** Сначала напряжение, потом частоту — иначе нестабильно.
2. **Менять память и напряжение одновременно.** Крашит Intel Software. Пошагово.
3. **Не смотреть на причины ограничения.** Если `GpuUtilizationLimited` — процессор
   не тянет, разгон GPU бессмысленен.
4. **Гнаться за >20 Гбит/с памяти.** Ползунок до 22, но чип SC20 — на 20. Выше лотерея.

## Про шунт-мод (справочно, вне проекта)

Единственный способ поднять лимит выше 226 Вт — снизить сопротивление шунта на входе
12V (параллельный резистор / проволочка). Датчик «видит» меньший ток → карта думает,
что потребляет меньше → лимит отодвигается. Требует пайки, **аннулирует гарантию**,
риск повреждения. Проект это **не** поддерживает и не будет поддерживать.
