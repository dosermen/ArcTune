# Архитектура

## Обзор

ArcTune — тонкая Python-обёртка над публичным IGCL API. Проект сознательно
минималистичен: низкоуровневый слой (`igcl/`) повторяет C API один-в-один, а
высокоуровневые модули (`telemetry`, `tuner`) добавляют типизацию, проверки и
удобство.

```
src/arctuner/
├── igcl/            Низкоуровневый слой — честное отражение IGCL.dll
│   ├── loader.py      Загрузка IntelControlLib.dll/ControlLib.dll, резолв ctl*
│   ├── types.py       C-структуры (_ctl_*_t) и enum'ы (ctypes), по igcl_api.h
│   └── api.py         Python-обёртки ctl* + маппинг ошибок (чтение и запись)
├── telemetry.py     Поиск Arc + чтение датчиков (read-only)
├── tuner.py         Запись настроек разгона (write, двухуровневые проверки)
├── logbook.py       Журнал изменений + расчёт отката (JSONL, read/write файла)
├── replay.py        Реплей инцидента: кольцевой буфер телеметрии (read-only)
├── autofind.py      Старый API autofind (совместимость, тесты)
├── autotune/        Общий движок авторазгона CLI и GUI
│   ├── engine.py      Адаптивный поиск, снаппинг к сетке IGCL, откат
│   ├── loader.py      Проверка нагрузки, внешний стресс-процесс
│   ├── watchdog.py    TDR, заморозка телеметрии, аварийная температура
│   └── profiles.py    JSON-профили параметров поиска
├── context.py       Общая сессия IGCL + запись через tuner.py (CLI и GUI)
├── gui/             GUI на PySide6 (extra `gui`, ниже)
│   ├── main.py        Точка входа `arctune-gui`
│   ├── window.py      Главное окно: вкладки, таймер, разводка сигналов
│   ├── worker.py      GpuWorker: все вызовы IGCL в отдельном QThread
│   ├── context.py     Реэкспорт GpuContext (совместимость импортов)
│   ├── charts.py      Графики QtCharts (живой, V/F)
│   ├── widgets.py     Карточки метрик, диалог подтверждения записи
│   └── tabs/          Мониторинг / Разгон / Вентиляторы / V/F / Журнал / Авторазгон
│       └── autotune.py  Вкладка «Авторазгон» (общий движок)
└── cli.py           Командная строка (argparse)
```

## Слои

### 1. `igcl/` — низкоуровневый слой

Задача — **честно** повторить IGCL.dll без абстракций:

- `loader.py` грузит `IntelControlLib.dll`/`ControlLib.dll` (IGCL API) через
  `ctypes.WinDLL`, находит функции по именам `ctl*`, отдаёт их с правильно
  заданными `argtypes`/`restype`.
- `types.py` описывает C-структуры через `ctypes.Structure` и `IntEnum` для enum'ов.
  Имена полей сохраняются как в C (`_ctl_power_telemetry_t` и т.п.) — чтобы сверка
  с `igcl_api.h` была тривиальной.
- `api.py` и `tuner.py` используют 27 функций `ctl*` (26 вызовов в 24 методах
  `api.py` плюс `ctlOverclockWriteCustomVFCurve` из `tuner.py`; ещё пять V2 Get
  вызываются динамически). Числовой код результата преобразуется в `IgclError`,
  наружу возвращаются dataclass-объекты.

**Принцип:** низкий слой не «улучшает» API — он его повторяет. Любая
специфика B580 живёт выше, в `telemetry`/`tuner`.

### 2. `telemetry.py` — чтение

Read-only. Безопасен по построению. Отдаёт снимок датчиков и **причины ограничения**
(GpuPowerLimited и т.п.) — то есть отвечает на вопрос «в чём карта упёрлась прямо сейчас».

**Ватты в телеметрии.** В структуре `ctl_power_telemetry_t` нет мгновенной строки «Вт» —
есть только накопительные счётчики энергии (`gpuEnergyCounter`/`totalCardEnergyCounter`
в джоулях) и проценты (`gpuPowerPercent`). `PowerMeter` считает среднюю мощность как
ΔE/Δt за интервал опроса — честно, без конверсии из процентов (процент зависит от
текущего лимита). Первый тик — только база (Вт нет), пауза >30 с или откат счётчика —
перебаза без выдуманных значений. На живой B580 (проверено read-only): GPU ≈ 68 Вт,
вся карта ≈ 120 Вт при 65% от лимита питания.

Отдельно `replay.py` держит кольцевой буфер последних снимков: при сбросе счётчика
энергии (признак перезагрузки драйвера) или по Ctrl+C буфер дампится в JSONL
(`~/.arctune/incidents`, ротация 20 файлов). Это read-only диагностика: дамп
фиксирует факты и триггер, но не устанавливает причину сбоя.

### 3. `tuner.py` — запись

Единственный модуль, способный что-то изменить. Все записи проходят **двухуровневую**
проверку: (1) жёсткие инварианты проекта, (2) поддерживаемый диапазон min/max/step/supported
из `ctlOverclockGetProperties`. Отказ — если хотя бы один уровень не пройден.

Каждое изменение дополнительно фиксируется в журнале (`logbook.py`), что даёт
историю и возможность отката командой `log --rollback`.

> Модуль написан так, чтобы **нельзя было** установить запрещённое значение
> (лимит >120%, тайминги и т.п.). См. [safety.md](safety.md).

### 4. `logbook.py` — журнал и откат

JSONL-журнал «что было → что стало». Новые записи только дописываются (`record()`
с `fsync`). Исключение — `mark_restored()`: он помечает запись восстановленной и
**атомарно перезаписывает файл целиком** (временный файл + `os.replace`), поэтому
журнал не является строго append-only на всех операциях. Прежняя запись через
режим `"w"` могла обнулить историю при сбое; текущая схема сохраняет старый файл
при ошибке.

`rollback_targets()` возвращает для каждого OC-поля самое старое исходное значение —
это цель отката. Записи вентиляторов (`fan[*]`) в цели отката не попадают: для них
есть отдельный `reset --fans`. Read-only операции в журнал не пишутся. Сброс OC
(`reset --oc` / кнопка сброса) **инвалидирует старые цели отката**: история
остаётся, но `log --rollback` после сброса уже не возвращает прежний разгон —
карта сброшена к дефолту, и восстанавливать старые значения из журнала нельзя.

### 5. `autotune/` — общий движок авторазгона

`engine.py` — один движок для CLI `autofind` и вкладки «Авторазгон» GUI:

- делает шаг от последнего стабильного значения, приводит кандидата к сетке
  `min/step` из IGCL (иначе `tuner` отклонил бы запись как некратную);
- проверяет шаг: нагрузка по дельте `activity_counter`, температура, watchdog;
- пишет **только** через переданный контекст (`GpuContext` в CLI и GUI),
  то есть через `tuner.py` с двухуровневыми проверками и журналом;
- при провале шага, отмене или исключении возвращает карту к последнему
  стабильному значению; если откат не удался — делает полный `reset_to_default`
  и честно сообщает, что состояние карты неизвестно.

Режим по умолчанию — `frequency` (частота вверх). `undervolt` через смещение
напряжения на B580 ограничен драйвером диапазоном `0…+` (min=0); движок не
обходит это ограничение, а останавливается с пояснением. Настоящий undervolt —
только кривая V/F.

`watchdog.py` проверяет TDR (Event ID 4101), «заморозку» телеметрии (счётчик
энергии не растёт при активности GPU) и аварийную температуру 85 °C. Watchdog
работает **только во время авторазгона**, а не как постоянный мониторинг.
`profiles.py` хранит параметры поиска в JSON и не применяет их к карте.
`autofind.py` оставлен как старый модуль совместимости и тестов; CLI и GUI
используют `autotune/engine.py`.

### 6. `gui/` — интерфейс (необязательный слой)

GUI не реализует логику — он её только запрашивает и показывает:

- `context.py` (общий, без Qt) владеет сессией IGCL (`ctlInit` → `ctlClose`) и пишет
  **исключительно** через `tuner.py`, то есть сохраняются оба уровня проверок и журнал
  `logbook`; `gui/context.py` — реэкспорт для существующих импортов;
- `worker.py` — `GpuWorker(QObject)`, перенесённый в `QThread`: handle не
  потокобезопасен, поэтому все вызовы к карте сериализуются в одном потоке.
  UI шлёт queued-слоты и получает сигналы — окно никогда не блокируется;
- вкладки (`tabs/`) — семь штук: Мониторинг / Разгон / Вентиляторы / V/F /
  Журнал / Авторазгон / Оверлей. Они только отображают данные и подтверждают запись:
  диапазоны спинбоксов приходят из `ctlOverclockGetProperties`, а потолки проекта
  (питание 120% / память 22 Гбит/с) накладываются поверх. Память 21–22 Гбит/с
  доступна только после отдельного предупреждения о превышении номинала SC20
  (21 работает, 22 драйвер может отклонить); в CLI выше 20 — только с `--force`.
  Питание выше 120% не разрешается нигде;
- вкладка «Авторазгон» шлёт конфигурацию в `GpuWorker`, движок пишет через
  `GpuContext`, а прогресс и живой мини-график приходят сигналами — окно не
  блокируется на время поиска;
- записи в GUI сопровождаются диалогом (по умолчанию активна «Отмена») и
  предпросмотром; каждое изменение попадает в тот же журнал, что и в CLI.

Софт-кривой вентиляторов в GUI нет: на B580 драйвер поддерживает только FIXED
(`supportedModes=0x2`), поэтому доступна лишь фиксация RPM.

Приложение зависит от PySide6 (extra `gui`); ядро `telemetry`/`tuner`/`igcl` от Qt
не зависит вовсе и работает без него.

## Ключевые дизайн-решения

**Почему ctypes, а не C-расширение.** IGCL — стабильный C API с плоскими структурами.
ctypes позволяет обойтись без компиляции, проще в отладке и вносит меньше порога
входа. Недостаток — нет проверки типов на этапе сборки; компенсируется юнит-тестами
на layout структур.

**Почему повторяем C-имена.** Чтобы любую находку из `igcl_api.h` можно было
механически перенести в `types.py`. Отказ от «красивых» Python-имен на низком слое
оправдан: он делает сверку с первоисточником тривиальной.

**Почему запись изолирована в `tuner`.** Единая точка контроля риска. Read-only
пути физически не могут ничего сломать, потому что не имеют доступа к set-функциям.

**Почему нет глобального состояния.** Каждая операция явно берёт handle устройства.
Нет сюрпризов из-за порядка вызовов, проще тестировать.

## Уровни доступа (если потребуется ниже IGCL)

IGCL — не самый низкий уровень. Если IGCL чего-то не даёт (например, страпов),
следующий уровень — IOCTL к `igdkmdnd64.sys`. Это **сложный, недокументированный
путь** (регистры контроллера памяти не раскрыты Intel, firmware-стек подписан).
Проект намеренно **не** спускается ниже IGCL: это выходит за рамки практической
реализуемости и описано здесь только для полноты картины.

## Обработка ошибок

Каждая `ctl*` возвращает числовой `_ctl_result_t`. Маппинг:
- `0` (`CTL_RESULT_SUCCESS`) → успех, дальше конвертируем в dataclass
- любое другое → исключение `IgclError` с кодом и расшифровкой

Исключения не «глотаются»: проблемы видны сразу, а не маскируются дефолтами.

## Тестирование

- **Тесты layout структур** — размер/смещение полей `_ctl_*_t` должны совпадать с C.
  Ловят опечатки в `types.py`.
- **Smoke-тесты** — проверяют загрузку `IGCL.dll` и обязательные функции; без
  библиотеки пропускаются.
- **Тесты логики** — диапазоны/проверки `tuner`, движок авторазгона, watchdog,
  профили, журнал и реплей мокаются без железа.
