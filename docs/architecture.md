# Архитектура

## Обзор

ArcTune — тонкая Python-обёртка над публичным IGCL API. Проект сознательно
минималистичен: низкоуровневый слой (`igcl/`) повторяет C API один-в-один, а
высокоуровневые модули (`telemetry`, `tuner`) добавляют типизацию, проверки и
удобство.

```
src/arctuner/
├── igcl/            Низкоуровневый слой — честное отражение IGCL.dll
│   ├── loader.py      Загрузка IntelControlLib.dll/ControlLib.dll, резолв ctl*
│   ├── types.py       C-структуры (_ctl_*_t) и enum'ы (ctypes), по igcl_api.h
│   └── api.py         Python-обёртки ctl* + маппинг ошибок (чтение и запись)
├── telemetry.py     Поиск Arc + чтение датчиков (read-only)
├── tuner.py         Запись настроек разгона (write, двухуровневые проверки)
├── logbook.py       Журнал изменений + расчёт отката (JSONL, read/write файла)
├── autofind.py      Автопоиск стабильной точки (TODO)
├── gui/             GUI на PySide6 (extra `gui`, ниже)
│   ├── main.py        Точка входа `arctune-gui`
│   ├── window.py      Главное окно: вкладки, таймер, разводка сигналов
│   ├── worker.py      GpuWorker: все вызовы IGCL в отдельном QThread
│   ├── context.py     Сессия IGCL + запись через tuner.py (rollback)
│   ├── charts.py      Графики QtCharts (живой, V/F)
│   ├── widgets.py     Карточки метрик, диалог подтверждения записи
│   └── tabs/          Мониторинг / Разгон / Вентиляторы / V/F / Журнал
└── cli.py           Командная строка (argparse)
```

## Слои

### 1. `igcl/` — низкоуровневый слой

Задача — **честно** повторить IGCL.dll без абстракций:

- `loader.py` грузит `IGCL.dll` через `ctypes.WinDLL`, находит функции по именам
  `ctl*`, отдаёт их с правильно заданными `argtypes`/`restype`.
- `types.py` описывает C-структуры через `ctypes.Structure` и `IntEnum` для enum'ов.
  Имена полей сохраняются как в C (`_ctl_power_telemetry_t` и т.п.) — чтобы сверка
  с `igcl_api.h` была тривиальной.
- `api.py` оборачивает каждую `ctl*` в Python-функцию, преобразует числовой код
  результата в исключение (`IgclError`) и возвращает dataclass-объекты.

**Принцип:** низкий слой не «улучшает» API — он его повторяет. Любая
специфика B580 живёт выше, в `telemetry`/`tuner`.

### 2. `telemetry.py` — чтение

Read-only. Безопасен по построению. Отдаёт снимок датчиков и **причины ограничения**
(GpuPowerLimited и т.п.) — то есть отвечает на вопрос «в чём карта упёрлась прямо сейчас».

**Ватты в телеметрии.** В структуре `ctl_power_telemetry_t` нет мгновенной строки «Вт» —
есть только накопительные счётчики энергии (`gpuEnergyCounter`/`totalCardEnergyCounter`
в джоулях) и проценты (`gpuPowerPercent`). `PowerMeter` считает среднюю мощность как
ΔE/Δt за интервал опроса — честно, без конверсии из процентов (процент зависит от
текущего лимита). Первый тик — только база (Вт нет), пауза >30 с или откат счётчика —
перебаза без выдуманных значений. На живой B580 (проверено read-only): GPU ≈ 68 Вт,
вся карта ≈ 120 Вт при 65% от лимита питания.

### 3. `tuner.py` — запись

Единственный модуль, способный что-то изменить. Все записи проходят **двухуровневую**
проверку: (1) жёсткие инварианты проекта, (2) поддерживаемый диапазон min/max/step/supported
из `ctlOverclockGetProperties`. Отказ — если хотя бы один уровень не пройден.

Каждое изменение дополнительно фиксируется в журнале (`logbook.py`), что даёт
историю и возможность отката командой `log --rollback`.

> Модуль написан так, чтобы **нельзя было** установить запрещённое значение
> (лимит >120%, тайминги и т.п.). См. [safety.md](safety.md).

### 4. `logbook.py` — журнал и откат

Append-only JSONL-журнал: «что было → что стало». `rollback_targets()` возвращает
для каждого поля самое старое исходное значение — это цель отката. Read-only
операции в журнал не пишутся.

### 5. `gui/` — интерфейс (необязательный слой)

GUI не реализует логику — он её только запрашивает и показывает:

- `context.py` владеет сессией IGCL (`ctlInit` → `ctlClose`) и пишет **исключительно**
  через `tuner.py`, то есть сохраняются оба уровня проверок и журнал `logbook`;
- `worker.py` — `GpuWorker(QObject)`, перенесённый в `QThread`: handle не
  потокобезопасен, поэтому все вызовы к карте сериализуются в одном потоке.
  UI шлёт queued-слоты и получает сигналы — окно никогда не блокируется;
- вкладки (`tabs/`) — только отображение и подтверждения: диапазоны спинбоксов
  приходят из `ctlOverclockGetProperties`, а потолки проекта (120% / 20 Гбит/с)
  накладываются поверх — выше можно только из CLI с явным `--force`;
- записи в GUI сопровождаются диалогом (по умолчанию активна «Отмена») и
  предпросмотром; каждое изменение попадает в тот же журнал, что и в CLI.

Приложение зависит от PySide6 (extra `gui`); ядро `telemetry`/`tuner`/`igcl` от Qt
не зависит вовсе и работает без него.

## Ключевые дизайн-решения

**Почему ctypes, а не C-расширение.** IGCL — стабильный C API с плоскими структурами.
ctypes позволяет обойтись без компиляции, проще в отладке и вносит меньше порога
входа. Недостаток — нет проверки типов на этапе сборки; компенсируется юнит-тестами
на layout структур.

**Почему повторяем C-имена.** Чтобы любую находку из `igcl_api.h` можно было
механически перенести в `types.py`. Отказ от «красивых» Python-имен на низком слое
оправдан: он делает сверку с первоисточником тривиальной.

**Почему запись изолирована в `tuner`.** Единая точка контроля риска. Read-only
пути физически не могут ничего сломать, потому что не имеют доступа к set-функциям.

**Почему нет глобального состояния.** Каждая операция явно берёт handle устройства.
Нет сюрпризов из-за порядка вызовов, проще тестировать.

## Уровни доступа (если потребуется ниже IGCL)

IGCL — не самый низкий уровень. Если IGCL чего-то не даёт (например, страпов),
следующий уровень — IOCTL к `igdkmdnd64.sys`. Это **сложный, недокументированный
путь** (регистры контроллера памяти не раскрыты Intel, firmware-стек подписан).
Проект намеренно **не** спускается ниже IGCL: это выходит за рамки практической
реализуемости и описано здесь только для полноты картины.

## Обработка ошибок

Каждая `ctl*` возвращает числовой `_ctl_result_t`. Маппинг:
- `0` (`CTL_RESULT_SUCCESS`) → успех, дальше конвертируем в dataclass
- любое другое → исключение `IgclError` с кодом и расшифровкой

Исключения не «глотаются»: проблемы видны сразу, а не маскируются дефолтами.

## Тестирование

- **Тесты layout структур** — размер/смещение полей `_ctl_*_t` должны совпадать с C.
  Ловят опечатки в `types.py`.
- **Smoke-тесты** — требуют реального устройства Arc; пропускаются, если его нет.
- **Тесты логики** — диапазоны/проверки `tuner` мокаются без железа.
